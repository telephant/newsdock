2 Sign-up, login, authorized read

sequenceDiagram
  participant U as Browser
  participant A as API (C-12/C-13)
  participant D as Postgres
  U->>A: POST /api/auth/signup (CORS, JSON)
  A->>D: lock, insert user (owner if first)
  A-->>U: 201 user
  U->>A: POST /api/auth/login (credentials: include)
  A->>D: load user, verify argon2id
  A->>D: insert session (sha256 of token)
  A-->>U: 200 + Set-Cookie (httpOnly, Lax)
  U->>A: GET /api/articles (cookie)
  A->>D: session join user, role check
  A-->>U: 200 articles
Check:
  • Is only the sha256 of the session token stored, never the cookie value?
  • Is the role read from the database on every request (so demotion is immediate)?
  • Does an unknown email take the same path and time as a wrong password?
  • Does sign-up avoid setting a cookie (one cookie-setting path)?
  • Is an Origin outside cors_origins refused on every write?

3 Data model

erDiagram
  users ||--o{ sessions : "has (cascade)"
  users {
    uuid id PK
    text email UK
    text password_hash
    text role "owner|admin|viewer"
    timestamptz created_at
  }
  sessions {
    text token_hash PK
    uuid user_id FK
    timestamptz created_at
    timestamptz last_seen_at
    timestamptz expires_at
  }
  agents ||--o{ api_keys : "unchanged"
  agents ||--o{ subscriptions : "unchanged"
Check:
  • Should agents carry an owner user id now, or stay global (assumed global)?
  • Is a text role with a CHECK constraint enough, or do you want a lookup table?
  • Does deleting a user remove their sessions and nothing else?

4 Live feed (EventSource with credentials)

sequenceDiagram
  participant U as Browser (EventSource)
  participant L as API live (C-14)
  participant D as Postgres
  U->>L: GET /api/live (withCredentials, cookie)
  L->>D: latest seq (start cursor)
  D-->>L: NOTIFY articles_new
  L->>D: list_new(cursor)
  L-->>U: event: article (id = cursor)
  L-->>U: : ping (keep-alive, re-check session)
  U->>L: reconnect with Last-Event-ID (CORS-allowed header)
Check:
  • Is NOTIFY only a wake-up while the data comes from the cursor query?
  • Does a logout or deletion end the stream within one keep-alive interval?
  • Is Last-Event-ID in the CORS allow list so reconnects resume?

5 Session lifecycle

stateDiagram-v2
  [*] --> Active: login ok
  Active --> Active: request (last_seen_at touched, at most once a minute)
  Active --> Expired: idle limit passed
  Active --> Expired: absolute limit passed
  Active --> Revoked: logout
  Active --> Revoked: user deleted
  Expired --> [*]: row purged
  Revoked --> [*]
Check:
  • Is an Expired session rejected even before its row is purged?
  • Does a role change keep the session but change what it may do?
