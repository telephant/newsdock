2 Primary sequence: resolving one service's settings

sequenceDiagram
  participant M as __main__
  participant S as Settings (C-11)
  participant E as os.environ
  participant F as newsdock.yaml
  M->>S: Settings()
  S->>E: NEWSDOCK_POLL_INTERVAL_SECONDS?
  E-->>S: set -> use it (env wins)
  S->>F: load (NEWSDOCK_CONFIG_FILE)
  F-->>S: common + ingester section
  S->>S: flatten, merge common under section
  S->>S: reject secret keys / unknown section keys
  S->>S: drop fields env already set
  S->>S: validators (poll floor 900 s)
  S-->>M: effective settings (logged, redacted)
Check:
  • Is "env wins even for the unprefixed aliases" what you expect (KAFKA_BOOTSTRAP_SERVERS)?
  • Should an unset NEWSDOCK_CONFIG_FILE silently skip the file (as designed), or should compose always set it?
  • Does failing at startup on a typo feel right, versus warning and continuing?

3 Heartbeat and healthcheck derived from config

sequenceDiagram
  participant W as Worker loop
  participant HF as /tmp/healthy
  participant D as Docker healthcheck
  participant C as app healthcheck module
  W->>HF: touch + write max_age (4/3 x poll interval)
  D->>C: run every 60 s
  C->>HF: read mtime and max_age
  C-->>D: exit 0 if age <= max_age else 1
Check:
  • Is 4/3 x poll interval (= today's 20 min at 900 s) the right slack for the ingester?
  • Is it fine that a hung loop is detected only after max_age, as today?
  • Do you accept one Python start per healthcheck run?

4 Web boot with runtime config

sequenceDiagram
  participant B as Browser
  participant N as Next server (C-15)
  participant F as newsdock.yaml
  participant A as API
  N->>F: read web section (per request)
  N->>N: env NEWSDOCK_WEB_* overrides
  B->>N: GET /
  N-->>B: HTML + config props (apiBaseUrl, pollMs)
  B->>A: GET apiBaseUrl/api/articles
  A-->>B: feed page
Check:
  • Is a per-request file read acceptable (tiny file) or should it be cached at server start?
  • Should an unreadable web file fall back to defaults (as designed) or fail the page?
  • Does the browser-visible API base match how you reach the API from your machine (127.0.0.1:8000)?
