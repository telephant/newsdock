2 One cycle (F-40)

sequenceDiagram
  participant C as C-51 cycle
  participant A as API /mcp
  participant O as Ollama
  participant F as C-56 files
  loop pages until short page or cap
    C->>A: list_new_articles(limit, cursor)
    A-->>C: articles, next_cursor
  end
  alt no articles
    C->>C: log empty window, stop
  else articles
    C->>C: count, rank, pick stories
    loop each ranked theme
      C->>O: titles of the theme
      O-->>C: one sentence (or error: unavailable)
    end
    C->>F: write HHMM.md, latest.md
    C->>A: ack_cursor(last next_cursor)
    C->>F: save baseline
  end
Check:
  • Is the ack strictly after the file write?
  • Can one failing Ollama call only affect its own section?
  • Does the baseline save come last, so a crash never double-counts a window?
  • Is an empty window free of any write or ack?

3 Loop and baseline lifecycle (F-41)

stateDiagram-v2
  [*] --> Cold: no file, corrupt file, or under 3 entries
  Cold --> Cold: cycle ok, entry added, ranked by volume
  Cold --> Warm: 3 entries stored
  Warm --> Warm: cycle ok, oldest of 24 dropped
  Warm --> Cold: file lost or corrupt
  Cold --> Sleeping: cycle ends
  Warm --> Sleeping: cycle ends
  Sleeping --> Cold: interval over, baseline cold
  Sleeping --> Warm: interval over, baseline warm
Check:
  • Does every path through a failing cycle still reach Sleeping (the loop never dies)?
  • Is losing the file always safe (back to Cold, no crash)?
  • Is 3 entries a sensible point to trust "rising"?
