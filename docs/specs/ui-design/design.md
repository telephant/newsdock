# ui-design — Design

Status: design written 2026-10-27 · detail in [design-detail.md](design-detail.md) (reference only) · diagrams in [diagrams/index.html](diagrams/index.html) · decision in [ADR-0022](../../adr/0022-shadcn-ui-on-tailwind-v4.md).

**Reading order:** this file → diagrams (each has a "Check" box) → ADR-0022. The spec is [spec.md](spec.md).

**Idea in one paragraph:** nothing moves in the data path. We add one CSS entry (`globals.css`) that holds all design tokens, copy a handful of shadcn primitives into `src/components/ui`, wrap the app in a theme provider and a new shell, and then replace the markup of each feature screen with those primitives. Behaviour, hooks, API calls and test-visible text stay as they are. Everything is checked with the existing vitest suite plus two small new scripts (colour literals, contrast).

## Flows

- **F-1 First paint and theme:** server renders `<html>` with no theme class; the `next-themes` inline script sets `dark` before paint from storage or the system. Diagram 2.
- **F-2 Feed render:** `Feed` fetches as today, renders `ArticleItem` cards inside `AppShell`; loading shows `ListSkeleton`, failure `ErrorAlert`. Diagram 3.
- **F-3 Confirmed destructive action:** button opens `AlertDialog`; confirm calls the existing handler. Diagram 3.

## Contracts

| Contract | Rule |
|---|---|
| Colour | Only semantic classes (`bg-background`, `text-muted-foreground`, `bg-primary`, `border`, ...). No hex, `rgb()`, `hsl()`, `oklch()` literals or palette classes outside `globals.css` and `components/ui` |
| Accessible names | Keep the text/roles the tests query ("Feed", "Live", "Log out", "filters" form, `role="alert"`, `role="status"`) |
| Wordmark | A `<span>`, not a link, so the nav still has the same links |
| `components/` | No data fetching; `ui/` is generated, feature code imports from it |
| Motion | Every animation is behind `motion-safe:` or `prefers-reduced-motion` |

## Tricky parts

- **Contrast of the green:** `#06C755`-like green with white text is below 4.5:1 **[assumption, check with the AC-11 script]**. Primary buttons use dark text on green; green text on white uses a darker `--primary-text` shade.
- **Dark-mode flash:** only avoided if the theme script runs before paint; keep `next-themes` in the root layout and do not gate it behind the async config `await`.
- **Dynamic layout:** the root layout awaits `connection()` per request; the provider is a client component inside it, so no change to that rule.
- **Tailwind scanning:** v4 detects sources automatically; generated `ui/*` files are inside `src`, so they are scanned.
- **Test churn:** restyling touches almost every component; change markup, not names, and run `pnpm test` after each screen.

## Failure modes

| Failure | Effect | Handling |
|---|---|---|
| Tailwind native binary missing in the image | Build fails | AC-14 image test; install on the same platform in `node:24-slim` build stage |
| CSS not shipped in standalone output | Unstyled page in container | AC-14 fetches the CSS link |
| Overly long CJK/URL titles | Card overflows | `min-w-0`, `break-words`, `line-clamp` (AC-4) |
| `localStorage` blocked | Theme not remembered | `next-themes` falls back to system; no error |
