2. Build once, run many times

sequenceDiagram
  participant B as Builder
  participant G as GDELT
  participant O as Ollama
  participant H as Harness
  B->>G: fetch N slots (GKG + Mentions)
  B->>B: collapse copies, event clusters, seeds
  B->>O: paraphrase and keywords per seed
  B->>B: check_fixture, write files
  H->>H: load fixture, embed corpus per prefix
  H->>H: run 4 methods, remove the seed
  H->>H: metrics, noise, sweep, bootstrap
  H-->>H: print tables, winners
Check
  • Why is the seed removed before scoring?
  • Is the same fixture used for every run (deterministic)?
  • Where is a weak query caught?
