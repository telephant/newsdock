2 Primary sequence: first-time setup to infra up

sequenceDiagram
  participant Dev as Developer
  participant M as make
  participant U as uv / pnpm
  participant D as Docker Compose
  participant K as kafka + postgres
  Dev->>M: doctor
  M-->>Dev: tool versions or MISSING tool
  Dev->>M: setup
  M->>U: uv sync --all-packages --locked, pnpm install --frozen-lockfile
  Dev->>M: check
  M->>U: ruff, mypy, import-linter, pytest, eslint, vitest
  Dev->>M: build
  M->>D: build 6 app images
  Dev->>M: up
  M->>D: up -d --wait kafka postgres
  D->>K: start, wait healthy
  M->>D: run topics, then run migrate
Check
  • If check fails on one app, does the output name the app and the rule?
  • What happens if .env is missing when you run up?
  • Is the order doctor, setup, check, build, up the order a newcomer would follow from the README?

3 Import rules enforced by make check

flowchart TB

    MAIN[__main__ + config] --> AD[adapters]

  end
  app --> CORE[newsdock_core]

  CORE -. forbidden .-> IO
  CORE -. forbidden .-> OTHER[any app]
  app -. forbidden .-> APP2[another app]
Check
  • Can domain/ still reach I/O indirectly, for example through a type from newsdock_core?
  • Does the api app's HTTP/MCP handler layer fit under adapters/?
  • Which rules are only reviewed, not enforced (DR-5, DR-8, DR-10…DR-12), and is that acceptable?

6 Stack lifecycle (make up / down)

stateDiagram-v2
  [*] --> Down
  Down --> InfraStarting: make up
  InfraStarting --> InfraHealthy: kafka + postgres healthy
  InfraStarting --> Failed: not healthy / no .env
  InfraHealthy --> TopicsReady: topics job ok
  TopicsReady --> Ready: migrate job ok
  Ready --> Ready: make up again (no change)
  Ready --> Down: make down
  Failed --> Down: make down
Check
  • Is running make up twice safe (AC-10, AC-11 say yes)?
  • Does make down keep the Postgres volume, and should it?
  • Where does a failed job leave the stack, and does the message say what to do?
