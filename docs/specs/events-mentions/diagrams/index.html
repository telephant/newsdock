2. Ingest, store and read

sequenceDiagram
  participant I as Ingester
  participant K as Kafka
  participant P as Processor
  participant S as Sink
  participant D as Postgres
  participant A as API
  I->>I: read lastupdate, 3 files per slot
  I->>K: publish lines (kind = gkg, events, mentions)
  Note over I: a 404 file stays pending, others go on
  K->>P: raw line
  P->>K: events.clean or mentions.clean or gkg.dlq
  K->>S: clean rows
  S->>D: upsert events, mentions (dedup in batch)
  S->>D: hourly delete older than 7 days
  A->>D: page of articles, then events by url_hash
  A-->>A: include=events adds events per article
Check
  • Does anything here make the GKG path wait for Events or Mentions?
  • If the sink is down, what stops and what is replayed?
  • Is one extra query per page acceptable for the read path?

3. Data model

erDiagram
  ARTICLES ||--o{ MENTIONS : "url_hash, no FK"
  EVENTS ||--o{ MENTIONS : "event_id, no FK"
  ARTICLES {
    char url_hash PK
    text title
  }
  EVENTS {
    bigint event_id PK
    date event_date
    text cameo_code
    real goldstein
    int num_mentions
    char source_url_hash
    timestamptz date_added
    timestamptz ingested_at
  }
  MENTIONS {
    bigint event_id PK
    char url_hash PK
    text source_name
    timestamptz mention_time
    smallint confidence
    timestamptz ingested_at
  }
  INGEST_FILE {
    text slot PK
    text kind PK
    text status
    int attempts
  }
Check
  • Is "an article's events = events it is mentioned in" the meaning you want?
  • Are the 20 events per article and the order by num_mentions sensible?
  • Is mention_count (rows we stored) next to GDELT's num_mentions confusing?

4. File state (ingest_file)

stateDiagram-v2
  [*] --> pending : listed in lastupdate
  pending --> pending : 404, empty, md5 mismatch (attempts + 1)
  pending --> published : rows sent
  pending --> failed : attempts reach max
  published --> [*]
  failed --> [*]
Check
  • Is "failed after 4 attempts" right for the new files too, same as GKG?
  • Should slots missed while the feature was off be back-filled (design says no)?
