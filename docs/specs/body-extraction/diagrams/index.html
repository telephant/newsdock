1. Components

flowchart LR
  A[(articles)] --> X[C-80 extractor]
  X --> F[C-81 fetcher: robots, address guard]
  F --> W[(open web)]
  X --> E[C-82 extract and split]
  E --> B[(C-83 article_bodies)]
  E --> P[(C-84 article_passages)]
  M[C-85 embedder, 2nd pass] --> P
  B --> API[C-86 API]
  P --> API
  API --> AG[agents: MCP and REST]
Check
  • Is the extractor the only box that touches the open web, and is that what you want?
  • Is it right that the ingester, processor and sink do not appear here at all?
  • Should passages be split by the extractor (as drawn) rather than by the embedder?

2. Discover, fetch, embed, search

sequenceDiagram
  participant X as Extractor
  participant D as Postgres
  participant W as Site
  participant M as Embedder
  participant A as API
  X->>D: discover: pending rows for new articles
  X->>D: pick newest pending, one per site
  X->>W: robots.txt, then the page (pinned address)
  W-->>X: HTML or an error
  X->>D: body and status, passages (no vector yet)
  M->>D: passages without a vector
  M->>D: store halfvec vectors
  A->>D: scope titles, body or all: up to 4 legs
  A-->>A: fuse by rank, best passage per article
Check
  • If the site is slow or blocks us, does anything else wait? (It should not.)
  • Between the body being stored and the vectors arriving, what does search return for that article?
  • Is "one page per site per round" polite enough for a site with thousands of articles a day?

3. Data model

erDiagram
  ARTICLES ||--o| ARTICLE_BODIES : "url_hash, cascade"
  ARTICLES ||--o{ ARTICLE_PASSAGES : "url_hash, cascade"
  ARTICLES {
    text url_hash PK
    bigint seq
    text url
    timestamptz ingested_at
  }
  ARTICLE_BODIES {
    text url_hash PK
    bigint seq
    text status
    text text
    smallint http_status
    smallint attempts
    timestamptz next_attempt_at
  }
  ARTICLE_PASSAGES {
    text url_hash PK
    smallint idx PK
    text text
    halfvec embedding
    text embedding_model
  }
Check
  • Is cascade from articles (7-day retention) the right way to remove text and vectors?
  • Is halfvec(768) acceptable for the passage vectors?
  • Is body_status = none the right answer for articles from before the feature?

4. Body status

stateDiagram-v2
  [*] --> pending : discovered
  pending --> ok : text stored
  pending --> blocked_robots : robots or Crawl-delay
  pending --> blocked_address : address or redirect refused
  pending --> http_error : 4xx
  pending --> not_html
  pending --> too_large
  pending --> no_text : empty or too short
  pending --> pending : 5xx or timeout, retry later
  pending --> failed : retries used up
Check
  • Are 4xx, not_html, too_large and no_text right as final (no retry)?
  • Are 3 attempts with 5 and 30 minute delays reasonable for 5xx and timeouts?
