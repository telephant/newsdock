2 Read with tone and a negativity filter (F-60, F-61)

sequenceDiagram
  participant A as Agent
  participant M as C-66 surface
  participant T as C-60 rules
  participant R as C-62 repo
  participant D as Postgres
  A->>M: search_articles(min_negativity=8, include=["tone_neg"])
  M->>T: parse_include, check_min_negativity
  alt bad input
    T-->>M: InvalidInclude / InvalidNegativity
    M-->>A: invalid_include / invalid_filter
  else ok
    M->>R: search(min_negativity=8, include=("tone_neg",))
    R->>D: WHERE tone_neg >= CAST(8 AS REAL) ORDER BY published_at DESC
    D-->>R: rows (NULL tone_neg rows are not matched)
    R-->>M: summaries with tone_neg filled
    M-->>A: articles[] via to_json: default keys + tone_neg
  end
Check:
  • Without include, is the response exactly today's (AC-1)?
  • Does an article with no tone_neg never come back when the filter is set (AC-9)?
  • Is the bad-input path decided before any SQL runs (AC-6, AC-13)?
  • Does semantic_search follow the same path in both legs (AC-10)?

4 Data and payload shape

classDiagram
  class articles {
    +tone real
    +tone_pos real
    +tone_neg real
    +tone_polarity real
    +word_count int
  }
  class ArticleSummary {
    +article_id, title, url, domain
    +published_at, themes, source_count, scores
    -tone, tone_pos, tone_neg, tone_polarity (excluded by default)
    +to_json(include)
  }
  class ArticleDetail {
    +tone, tone_pos, tone_neg, tone_polarity
    +word_count
  }
  articles --> ArticleSummary : fills only requested names
  articles --> ArticleDetail : fills all four
Check:
  • Is every new payload key backed by an existing column (no migration)?
  • Are the four fields hidden from every default dump, so streams and the live feed cannot leak them?
  • Does the detail return all four numbers unconditionally (AC-8)?
