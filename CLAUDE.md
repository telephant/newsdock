# newsdock

News "dock" for AI agents: ingests the GDELT GKG feed every 15 min, cleans it with a Python Kafka processor, keeps 7 days in Postgres, and serves it to agents through an MCP server and REST. Local docker-compose only. Milestone 1 (MVP) is a walking skeleton.

## Repo layout (monorepo, Python + TypeScript in one git repo)
- `apps/<service>/` one deployable per folder: `ingester`, `processor`, `sink`, `embedder`, `extractor`, `api`, `agent` (Python) and `web` (Next.js + TS). Each app owns its dependency file and Dockerfile.
- `packages/core/` shared pure Python code (GKG parsing, URL normalisation, models, contracts); `packages/db/` SQLAlchemy engine, config and metadata; `packages/config/` the layered config loader (`newsdock_config`, ADR-0013); `packages/embedding/` the one Ollama `/api/embed` client, the document/query text prefixes and vector validation, plus a `FakeOllama` for tests (`newsdock_embedding`, ADR-0024; adapters import it, `domain/` never does). Apps may import `packages/*`, never another app.
- `agents/<name>/` independent agent servers (clients of the platform, ADR-0029): each is its own project with its own Dockerfile, compose file and `.env`, importing nothing from `apps/*` or `packages/*`; the app rules below do not apply to them (`check_layout.py` only requires Python under `src/<name>/` or `tests/`).
- `infra/` docker-compose, `infra/config/newsdock.yaml` (the one config file), Alembic migrations, check scripts. `docs/` specs and ADRs.
- The only link between Python and TS is the REST/OpenAPI contract; generate the UI's types from it instead of hand-writing them.
- Python: one `uv` workspace at the root (planned); web: its own `package.json` in `apps/web`. CI jobs run only for the apps whose files changed.

## Directory rules (foundation spec §6, DR-1…DR-13; enforced by `make check` once M0 builds it)
- Repo root: only `apps/`, `packages/`, `infra/`, `docs/`, `.github/` and root tooling files. New app or top-level folder needs an ADR.
- Python app: `pyproject.toml`, `Dockerfile`, `README.md`, `src/newsdock_<app>/`, `tests/`. Code only under `src/`, tests only under `tests/` (`unit/` mirrors `src/`, `integration/` marked).
- Inside every Python app: `__main__.py` wires only; `domain/` is pure logic (stdlib, pydantic, `newsdock_core` only); `adapters/` holds all I/O. Adapters import domain, never the reverse.
- Apps import `packages/*` only, never another app. `newsdock_core` imports no app and no I/O library. Shared contracts live once in `newsdock_core.contracts`; GDELT fixtures only in `packages/core/tests/fixtures/`.
- Env is read only in `config.py`. SQL and query building only in `adapters/` and Alembic migrations (`infra/migrations/versions/NNNN_<name>.py`), always parameterized. DB access is SQLAlchemy 2 via the shared package `packages/db` (`newsdock_db`); `domain/` and `newsdock_core` never import it.
- Web `src/`: `app/` thin routes, `features/<name>/` feature code, `components/` shared UI without data fetching, `lib/api/` generated client (never hand-edited).
- Web styling (M2c `ui-design`, ADR-0022): shadcn/ui on Tailwind v4; `components/ui/` is generated by the shadcn CLI (after `shadcn add`, change its `cn` import to `@/lib/utils`). Colours only as semantic token classes from `src/app/globals.css` (light + dark sets, hex tokens so contrast can be checked); no hex, palette classes or `dangerouslySetInnerHTML` elsewhere (`make style-web`, part of `check-web`). System fonts only. Destructive actions confirm through `useConfirm` (`components/ConfirmDialog.tsx`), whose `confirm` prop on a screen is the test seam. Animations are `motion-safe:` only.

## Workflow
- A local pass is not CI: the first GitHub run found a non-existent action tag (`setup-uv@v10`), a test PATH that hid a real `/usr/bin/docker`, and a job without pnpm. After touching `.github/`, push and read the run (`gh run watch`, `gh run view --log-failed`).
- Docker tests never share the dev stack's ports (incident 2026-10-28: tests truncated the dev database, because `docker compose up --wait` exits 0 even when a container cannot bind its port). Postgres tests take the `side_db` fixture (`newsdock_db.testing.side_postgres`: own compose project, free port, checks the container is running, healthy and owns the port). Modules that start a whole stack or Kafka on fixed ports (5433, 29092, 8000, 3000) are refused in setup by `infra/scripts/dev_stack_guard.py` while those ports are busy; stop the dev stack (`make down`) to run them. Never write a Docker test that trusts `compose up`'s exit code or a fixed host port.
- Work follows the spec pipeline: `/spec-init` → `/spec-design` → `/spec-plan` → `/spec-implement` → `/spec-verify`, one folder per feature under `docs/specs/<name>/`.
- Implement one task at a time from `docs/specs/mvp/tasks/T-NN.md`, test first. Use only the context that task names.
- Every acceptance criterion `AC-n` in `spec.md` must end up covered by a test or a manual check listed in `tests.md`.
- When a doc changes, update every file that repeats the fact (ids, topic names, tool names, statuses) in the same edit, and note stale downstream files.
- Changing a decided item (`D-n` in the spec, an Accepted ADR) needs the user's approval; record the change in the spec/ADR with the date.

## Architecture (ids are used in all docs)
- C-1 Ingester → C-2 Kafka (default topics `gkg.raw`, `gkg.clean`, `gkg.dlq`, plus `events.clean` and `mentions.clean` since M3c: `gkg.raw` and `gkg.dlq` also carry Events and Mentions lines, told apart by a `kind` field, ADR-0032; names are config, ADR-0013) → C-3 Python processor (stateless: parse, validate, route) → C-4 sink + retention → C-5 Postgres 16 + pgvector (unused in the MVP; holds the title embeddings since M3 `semantic-search`).
- C-6 API: one FastAPI process serving MCP (streamable HTTP, `/mcp`) and REST (`/api/*`) over one service layer.
- C-7 demo agent (MCP client + Ollama on host), C-8 Next.js UI (REST only).
- C-80…C-87 body extraction (`apps/extractor`, ADR-0034…0037): the only component that talks to the open web. Its discovery pass queues each new canonical article in `article_bodies` (`pending`, newest first, last `backfill_hours` on the first run, no trigger and no sink change); it fetches one page per site at a time (`per_host_delay_seconds`, a site's `Crawl-delay` up to `max_crawl_delay_seconds`), honours robots.txt (Protego, honest user agent), resolves names itself and refuses non-public addresses and ports other than 80/443, follows redirects by hand re-checking each hop, sends no cookies, caps bytes and redirects, extracts with `trafilatura`, caps the text at `text_cap_chars` and splits it into ~1,000-character passages in `article_passages`. It reads and writes Postgres only (role `extractor_rw`, no Kafka) and sits on the `data` network, so the address guard is the only wall against SSRF. The embedder's second pass embeds the passages (`halfvec(768)`, titles first in each round). The API never fetches pages (AC-15). Retention deletes with the article (cascade).
- C-35 embedder worker (`apps/embedder`): polls Postgres for canonical articles with no embedding (or one from another model), embeds titles through Ollama on the host and stores the vector; independent of the sink and Kafka (ADR-0024). C-37/C-38 semantic search in the API: HNSW cosine vector leg plus a full-text keyword leg, fused by reciprocal rank, behind the MCP tool `semantic_search` (ADR-0025).
- C-50…C-58 and C-70…C-79 what-happen digest agent: an **independent server**, `agents/whathappen/` (ADR-0029), not part of the platform. Own `pyproject.toml`/lockfile, Dockerfile, `compose.yaml`, Makefile and a `.env` that is ignored by version control; imports no platform code and joins no platform docker network. It reads news through MCP with its own key (`WHATHAPPEN_API_KEY`, created in the website at `/admin/agents`; `list_new_articles` with `include=["tone_neg"]`), merges headlines about one event (`LexicalGrouper` behind the `StoryGrouper` port: shared significant words, 48 h from the seed, never two pages of one domain, a trailing ` | Outlet` dropped), scores each group `sources × (1 + tone_neg / 10)` (coverage only if the platform returns no tone), lists groups carried by 2+ outlets as a Top 5 and as sections labelled by a vote over theme prefixes (`WHATHAPPEN_SECTION_LABELS` overrides the map), asks Ollama for one sentence only for groups with 2+ distinct headlines, and writes `agents/whathappen/output/YYYY-MM-DD/HHMM.md` + `latest.md` (first line `<!-- whathappen:story-first -->`). Order is file, then `ack_cursor`; an empty window writes nothing; an hour with no story carried by 2+ outlets writes a note and acks; a model failure only costs one line. In Docker it reaches the platform as host name `api` (the MCP endpoint answers 421 to Host names outside `localhost`, `127.0.0.1`, `api`).
- Flink was deliberately dropped (ADR-0001). Do not reintroduce stateful stream engines in the MVP.

## Fixed names (do not rename without updating all docs)
- MCP tools: `search_articles`, `get_article`, `list_new_articles`, `submit_analysis`, `ack_cursor` (M2 agent-platform, ADR-0017), `semantic_search` (M3 semantic-search: `query`, `mode` = `hybrid`|`vector`, `scope` = `titles`|`body`|`all`, the `search_articles` filters, `limit`; result `{articles (with score, matched_by), mode, degraded}`; errors `invalid_query`, `embedding_unavailable`).
- Tone arguments (M3b `tone-in-summary`, ADR-0030): `search_articles`, `semantic_search` and `list_new_articles` take `include` (a list of `tone`, `tone_pos`, `tone_neg`, `tone_polarity`; adds those GDELT numbers to each article, `null` when it has none; without it the payload is unchanged), and `search_articles`, `semantic_search` and `GET /api/articles` take `min_negativity` (0–100, strict number; keeps articles whose `tone_neg` is at or above it, none without tone). REST spells them `include=tone,tone_neg` and `min_negativity=8`. Errors: MCP `invalid_include` / `invalid_filter`, REST/subscription 422 (`invalid_include`, `invalid_filter`). `get_article` and `GET /api/articles/{id}` always carry all four tone numbers. The four fields are `exclude=True` on `ArticleSummary` and written only by `to_json(include)` / `dump_page`, so streams and the live feed are unchanged; `apply_filters` compares `tone_neg >= CAST(:v AS real)` because the column is a float4.
- Events (M3c `events-mentions`, ADR-0032/0033): `search_articles`, `semantic_search` and `list_new_articles` also accept `events` in `include` (REST `include=events`, also with tone names: `include=tone_neg,events`); each article then carries `events`, the GDELT events it is mentioned in (found through `mentions.url_hash`, at most `api.events_per_article` = 20, most mentioned first, `[]` when none), each `{event_id, date, cameo_code, cameo_root, goldstein, quad_class, num_mentions, num_sources, avg_tone, actor1, actor2 {code, name, country, type}, location {name, country, adm1, lat, lon}|null, source_url, mention_count}` (`num_mentions` is GDELT's count, `mention_count` the real mention rows we stored, derived rows excluded; an article also gets the events of its story's copies, ADR-0038). `get_article` and `GET /api/articles/{id}` always carry `events`. `events` is `exclude=True` on `ArticleSummary` like the tone fields, so streams and the live feed are unchanged. An unknown name is still `invalid_include` / 422. The names are checked in `domain/include.py` (`tone.py` re-exports them). The documentation-only OpenAPI twins are `ArticleSummaryEvents` and `FeedPageEvents`. Ingest: the ingester also fetches `*.export.CSV.zip` (Events, 61 columns) and `*.mentions.CSV.zip` (Mentions, 16) with their own state in `ingest_file`; settings `ingester.fetch_events|fetch_mentions`; raw keys `slot:kind:row_no`; the processor routes by `kind` to `events.clean` / `mentions.clean`; the sink upserts (newer `date_added` / `mention_time` wins) and the hourly retention deletes both tables by `ingested_at` with the same `retention_days`.
- Body (M3d `body-extraction`, ADR-0036/0037): `get_article` and `GET /api/articles/{id}` always carry `body` (the text, null unless the status is `ok`) and `body_status` (`ok`, `pending`, `blocked_robots`, `blocked_address`, `http_error`, `not_html`, `too_large`, `no_text`, `failed`, or `none` when the article has no row); `search_articles`, `semantic_search` and `list_new_articles` accept `body` in `include` (REST `include=body`, mixable with tone and events; `body` is `exclude=True` on `ArticleSummary` like the others, so streams and the live feed are unchanged). `semantic_search` takes `scope`: `titles` (the default, `api.semantic_default_scope`; payload byte-identical to before), `body` (passages only) or `all` (both, fused by reciprocal rank); `body` and `all` add `passage` (the best matching passage, null when only the title matched) to each result and `matched_by` may name `body_vector` and `body_keyword` next to `vector` and `keyword`; an unknown scope is `invalid_scope`; `embedding_unavailable` / `degraded` behave as for titles. Settings: `extractor.*` (concurrency, per_host_delay_seconds, max_crawl_delay_seconds, max_bytes, max_redirects, max_attempts, retry_backoff_minutes, min_chars, text_cap_chars, passage_chars, retention_days, backfill_hours), `embedder.passage_batch_size`, `api.semantic_default_scope|semantic_passage_candidates`. Compose service `extractor` (profile `apps`, heartbeat healthcheck, no dependency on Kafka).
- Public article id is `url_hash` (sha256 of the normalized URL). `seq` (bigserial) drives the cursor, never expose it raw: the cursor is opaque base64.
- Tables: `articles` (canonicals; `story_key` NULL = pre-M2a row; `embedding vector(768)` and `embedding_model` NULL until the embedder fills them, migration 0008, canonical rows only, HNSW cosine index, a GIN full-text index on `to_tsvector('english', title)` and, from migration 0009, the partial index `ix_articles_unembedded (seq) WHERE embedding IS NULL`, the embedder's queue), `analyses`, `ingest_slot`, `article_sources` (copies; PK `url_hash`, FK → canonical, CASCADE), `users` (unique lower-cased email, role `owner|admin|viewer`, argon2id hash), `sessions` (sha256 of the cookie value, FK → users CASCADE), `agents` (`owner_id` nullable FK → users, `ON DELETE SET NULL`: NULL = no owner, ADR-0023), `password_resets` (migration 0010: `user_id` PK → users CASCADE, `code_hash`, `expires_at`, `attempts`, one open code per user, ADR-0026), `events` (PK `event_id`, curated subset of the 61 Events columns), `mentions` (PK `(event_id, url_hash)`; since migration 0013 a `derived` flag marks the rows the sink writes for the canonical when a copy of its story is mentioned, ADR-0038) and `ingest_file` (PK `(slot, kind)`, fetch state of the Events and Mentions files), all from migration 0011 with no foreign keys: events and mentions join articles by `url_hash` (ADR-0033). `article_bodies` (PK `url_hash` → `articles` CASCADE; `seq`, `status`, `text`, `http_status`, `attempts`, `next_attempt_at`, `fetched_at`; the queue is `status = 'pending'`) and `article_passages` (PK `(url_hash, idx)` → `articles` CASCADE; `text`, `embedding halfvec(768)`, `embedding_model`; HNSW cosine, GIN full-text, partial index where no vector), both from migration 0012 (ADR-0036). Slot format: `YYYYMMDDHHMMSS`.
- Dead-letter reasons: `missing_url`, `missing_title`, `missing_event_id` (Events and Mentions), `bad_column_count`, `bad_field`; dead-letter messages carry `kind` (`gkg` by default).
- Agent score payload: `{relevant, score (0–1), reason}`; `submit_analysis` accepts any JSON object.
- Story grouping (M2a): key = `newsdock_core.stories.story_key` (normalized title, fixpoint suffix-strip) within ± `NEWSDOCK_STORY_WINDOW_HOURS` (48), and never into a story that already has a different page of the same domain (`can_join`, ADR-0012 amendment); API fields `source_count` and `sources[]`.

## GDELT rules (verified in `docs/research.md`)
- Follow redirects; `http://` URLs in the index redirect to `https://`.
- A slot can be listed yet return 404 or an empty body. Treat 404, empty body or md5 mismatch as "retry later" (slot stays `pending`, max 4 attempts), never as an error or as data.
- Poll interval is configurable but never below 900 s.
- GKG rows are 27 tab-separated columns with no header. The title is inside column 27 (`<PAGE_TITLE>`), not its own column. Empty themes, persons and orgs are normal (do not dead-letter them); only a missing URL or title is a bad row.
- There is no article body in GKG. Article pages are fetched only by the `extractor` app (M3d, ADR-0035: robots.txt, an honest user agent, one request per site at a time, public addresses only); nothing else in the platform may fetch them, and the API makes no outbound request to article sites.

## Code conventions
- Backend: Python 3.12+, fully typed, async where I/O bound, tests with pytest. Frontend: Next.js with TypeScript.
- All consumers are at-least-once with manual offset commits; all writes must be idempotent (`ON CONFLICT (url_hash) DO NOTHING`).
- SQL is always parameterized. Render agent payloads in the UI as escaped text, never HTML.
- Secrets live in `.env` (git-ignored). Never commit credentials or put them in docs.
- Auth (M2 `agent-platform`, ADR-0016/0017): `/mcp` needs `Authorization: Bearer ndk_<prefix>_<secret>` unless `api.auth_required: false`; keys are issued by the agent's owner in the UI or by the operator (`make agent-create`, `NEWSDOCK_ADMIN_TOKEN` in `.env`), stored as prefix + sha256, shown once. Authenticated agents own a server-side cursor (`agent_cursors`, advanced only by `ack_cursor`) and a per-minute rate limit. `GET /api/articles*` needs a login or an agent key (see Accounts).
- Accounts (M2 `ui-login`, ADR-0020/0021): humans sign up (open by default, `api.auth_signup_open`; the first account is the `owner`, later ones `viewer`) and log in with an httpOnly `newsdock_session` cookie (DB session, 12 h idle / 7 d absolute). Roles: `viewer` reads and sees `/live`; every role (`viewer`, `admin`, `owner`) manages its own agents, keys and subscriptions; `owner` also manages users (the last owner cannot be removed) and sees every agent, including ones with no owner. Agent ownership (M2d, ADR-0023): `agents.owner_id` records the creating user; the repos take a required `AgentScope` (`scope_for(principal)`: all for the `owner` role and the admin token, otherwise the caller's own), and a foreign, ownerless-to-them or unknown agent id is a plain 404. Agents made with `make agent-create` (admin token), agents from before 0007 and agents whose creator was deleted have no owner: only the `owner` role and the token manage them. `admin` and `viewer` now hold the same permissions. Limits (M2e `signup-rate-limit`, `domain/signuplimit.py`): `POST /api/auth/signup` counts attempts that passed validation per peer address (`auth_signup_max_per_address`, 5) and in total (`auth_signup_max_total`, 50) per `auth_signup_window_minutes` (60) and answers 429 `too_many_signups` with `Retry-After` before hashing; `agents_max_per_user` (10, disabled agents count) makes `POST /api/admin/agents` answer 409 `too_many_agents` for non-owner users (owner role and token exempt); `0` turns a limit off; in memory, one API worker, `X-Forwarded-For` ignored. One resolver (`adapters/principal.py`) turns an `Authorization` header (agent key, else the admin token) or the cookie into a principal; a header, if present, decides alone. `NEWSDOCK_ADMIN_TOKEN` stays as the CLI path (`/api/admin/*`, `make agent-create`) and the only way to reset a password (`make user-reset-password`). The browser calls the API directly with credentialed CORS (explicit origins), so page and API must share a hostname (the web proxy redirects `localhost` to `127.0.0.1`); writes need a JSON body and an allowed `Origin`. `GET /api/live` is the live-feed SSE for sessions. Routes: `/api/auth/{signup,login,logout,me}`, `/api/users*` (owner), `/api/admin/users/reset-password` (token only).
- Password reset (M2f `forgot-password`, ADR-0026/0027): `POST /api/auth/forgot-password` (always 202 `{"ok": true}` for any well-formed email; the lookup, code, upsert and SMTP send run in a background task after the response so timing does not reveal accounts), `POST /api/auth/reset-password` (`{email, code, password}` → 204; every wrong, expired, used or unknown case is one 400 `invalid_or_expired_code`; success ends the user's sessions and clears the login lockout) and `GET /api/auth/options` (`{password_reset_enabled}`). Errors: 422 `invalid_email`/`invalid_password`, 429 `too_many_reset_requests` / `too_many_reset_attempts` with `Retry-After`, 503 `password_reset_unavailable` when off. The code is six digits stored as HMAC-SHA256 keyed with `NEWSDOCK_RESET_CODE_SECRET` (≥ 32 chars) over `user_id:code`; the mail has the code and no link; nothing about the code, address or passwords is logged. The feature is on only with `api.smtp_host`, `api.mail_from` and the secret; `NEWSDOCK_SMTP_PASSWORD` is optional (env only, like the secret). Settings: `api.smtp_host|port|security (starttls|ssl|none; none = loopback only, no credentials)|user|timeout_seconds`, `mail_from`, `auth_reset_code_minutes|max_attempts|max_per_email|max_per_address|max_tries_per_address|window_minutes`. Limiters are in memory, one API worker. Web: `/forgot-password`, `/reset-password`, link on `/login` only when the options say enabled.
- Push (M2 `push-delivery`, ADR-0018/0019): agents manage their own subscriptions (`/api/subscriptions`, body = filter: optional `theme`, `domain`, `text` and, since M3b, a numeric `min_negativity`) and read `GET /api/subscriptions/{id}/stream` (SSE; event id = the opaque cursor; resume with `Last-Event-ID`; a keep-alive tick re-checks the key). New rows wake streams through Postgres `NOTIFY articles_new` (trigger in migration 0005); the notification is only a wake-up, the data always comes from the `seq` cursor query.
- Semantic search (M3 `semantic-search`, ADR-0024/0025): the `embedder` app embeds `articles.title` with `nomic-embed-text` (768 dimensions) through Ollama on the host (`ollama pull nomic-embed-text`); the worker takes the newest rows with no vector (partial index, so the cost does not grow with the rows already embedded) and clears vectors of any other model once at start so they are re-embedded; `semantic_search` embeds the query the same way (`newsdock_embedding`), then runs a vector leg (cosine, only rows whose `embedding_model` equals the configured one, `hnsw.iterative_scan = relaxed_order` so filters still return rows) and, in `hybrid` mode, a full-text leg, fused by reciprocal rank (`domain/ranking.py`, k = `semantic_rrf_k`). Both legs use the one filter implementation `apply_filters`. If Ollama is down, `vector` fails with `embedding_unavailable` and `hybrid` returns the keyword leg with `degraded: true`; ingestion never depends on it. Settings: `common.embedding_model|dimension|document_prefix|query_prefix|ollama_url` (env `OLLAMA_URL`), `embedder.*`, `api.semantic_*`. DB role `embedder_rw` may update only the two embedding columns. Measure with `make eval-search` (recall@5 and MRR; the current 40-title set is too easy to tune on, see the spec backlog).
- The demo agent must have no database credentials and no route to Postgres or Kafka; it reaches data only through the MCP server (AC-13).

## Configuration (ADR-0013, spec `externalize-config`)
- Every tunable lives in `infra/config/newsdock.yaml`: a `common:` parent inherited by the `ingester`, `processor`, `sink`, `embedder`, `api`, `agent`, `web` sections. Precedence: env > file > code defaults. Nested keys flatten with `_` to the setting name (`kafka.topics.clean` → `kafka_topics_clean` → env `NEWSDOCK_KAFKA_TOPICS_CLEAN`); agent env prefix is `NEWSDOCK_AGENT_`.
- Secrets (`DATABASE_URL`, passwords) stay in `.env`/the environment; the loader rejects secret-looking keys in the file. The file holds the defaults, so an empty file changes nothing.
- Web login keys (ui-login): `web.session_cookie` (must equal `api.auth_cookie_name`) and `web.login_required` (`false` only with `api.auth_required: false`); setting names containing password/secret/token/credential are rejected in the file (use e.g. `auth_min_pw_length`, `cors_allow_cookies`).
- A new setting = a field on that app's `Settings` (extends `newsdock_config.LayeredSettings`) with the old literal as default, plus its row in the file if you want it visible. `make config-python` fails on unknown keys, values that differ from defaults, and tunable literals (topic names, retry/retention constants) reintroduced in code. Manual offset commits and `follow_redirects=True` stay in code (invariants, not tunables).
- Healthchecks are app code (`newsdock_<app>.adapters.healthcheck`); the worker writes its own allowed heartbeat age into `heartbeat_file`. Host ports come from `.env` (`API_PORT`, `WEB_PORT`, `POSTGRES_PORT`); container ports are fixed. The web app reads its `web:` section at server start (no rebuild to change the API base).

## Commands (run from the repo root; `make help` lists them)
- `make doctor` check tools; `make setup` install from lockfiles; `make check` everything (`check-python`, `check-web`, `docs-check`).
- `make test APP=<ingester|processor|sink|api|agent|web>` one app's tests; `make test-rules` proves each enforced rule fails when violated (`test-rules-python` skips the pnpm-dependent ones; CI uses it); `make test-infra [SCENE=<db|kafka|sink|api|pipeline|e2e|stack|images>]` Docker tests, scoped to one scene or all (needs Docker, ports 5433 and 29092 free, no `.env` surprises: it backs up and restores your own).
- `make build [APP=<name>]` images (`newsdock-<app>:dev`, `newsdock-migrate:dev`); `cp .env.example .env` then `make up` / `make down`; `make topics`, `make migrate` are idempotent.
- The what-happen agent has its own commands, run from `agents/whathappen/` (or `make -C agents/whathappen <target>`): `once` (one cycle, needs `.env` with `WHATHAPPEN_API_KEY`), `run`, `clean-old` (dry run) and `clean-old-yes` (delete the old theme digest's output),  `up`/`down`/`logs` (Docker), `check` (ruff, mypy, tests). It is not covered by the root `make check`; a CI job for `agents/` is a follow-up.
- `make agent-create NAME=<name>` registers an agent; `make user-reset-password EMAIL=<email>` resets a user's password (prompts, owner recovery); both need `NEWSDOCK_ADMIN_TOKEN` in `.env` and the api up.
- Raw compose needs the env file: `docker compose --env-file .env -f infra/compose.yaml ps` (compose looks for `.env` next to the compose file otherwise).
- Python: `uv run ...` (never `pip`); one workspace, `uv sync --all-packages --locked`. Web: `pnpm --dir apps/web run <script>`; Node 24 comes from pnpm, not the system.
- Quality tools: ruff (lint, format, `TID251` bans `os.environ`/`os.getenv` outside `config.py`), mypy strict with the pydantic plugin, import-linter contracts in `pyproject.toml`, `infra/scripts/check_layout.py`, `infra/scripts/check_docs.py`, `infra/scripts/check_config.py` (`make config-python`), `infra/scripts/check_web_style.py` (`make style-web`, part of `check-web`: web colours only from tokens in `globals.css`, no `dangerouslySetInnerHTML`, token contrast ≥ AA; `components/ui` is generated by the shadcn CLI).
